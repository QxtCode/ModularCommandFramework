## 延迟特征

| 百分位 | 约值 | 原因 |
|--------|------|------|
| P50 | ~100ms | 一个主循环周期 |
| P95 | ~300ms | 两个周期 + 线程调度 |
| P99 | ~500ms | 最大等待 + OS 调度抖动 |

延迟主要来源是 `ShellEngine::WaitForWork()` 的 100ms 超时。
命令在工人线程上快速完成，但结果可见性取决于主循环下一轮 `DrainResults()`。

## 限制与调优

### 池耗尽

当所有 Task 槽位被占用时, `TasksPool::Acquire()` 返回 `nullptr`。
引擎输出 `[ERROR] All tasks busy` 并跳过命令。

**调优:** 增大 `pool_size` 或 `--pool_size=N`。

### 工人饱和

当所有工人忙碌时, 任务在线程池中排队。线程池队列无限 —
极端情况下可能导致内存增长。

**调优:** 增大 `workers`。经验公式: `workers = CPU核心数 - 2`。

### 主循环周期

`WaitForWork()` 超时 (100ms) 是结果可见性的最小延迟。
降低超时可减少延迟, 但会增加空闲 CPU 使用。

**调优:** 修改 `ShellEngine::WaitForWork()` 超时参数。

### v2.6 改进: 不再有 Emit 阻塞

快照式 Emit 消除了慢 Slot 对 RemoveSignal/UnloadModule/Dispatch 的连锁阻塞。
模块卸载不再需要等待慢回调完成，可用性大幅提升。
详见 [12-并发审计](12-并发审计.md)。

## 配置参考

配置由 `ShellConfig` 在 `main.cpp` 启动时加载。  
加载流程见 [07-架构概览](07-架构概览.md)。

### test_shell.cfg（放在可执行文件旁边）

```ini
# 引擎
pool_size = 8
workers = 4

# 路径
plugin_dir = plugins

# 日志级别 (debug | info | error | fatal)
log_level = info

# 告警 (0 = 不告警)
queue_warn = 0
```

### 命令行覆盖

```bash
./test_shell --pool_size=32 --workers=12 --plugin_dir=./my_plugins
```

优先级: 命令行 > 配置文件 > 默认值。
