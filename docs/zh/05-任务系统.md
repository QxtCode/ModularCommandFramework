# 任务系统 — 分片、暂停、取消

一个 Task 是一串"分片"。每个分片 = 一次 EventBus 发射。分片之间可以暂停、恢复、取消。

## 数据流向（v2.5）

```
工人: while(task->Step(bus)) {}
  → bus.Emit("Calc.add", pack)     // 模块回调执行
  → ResultStore::PushResult(...)   // 结果落入仓库
  → tasks.Release(task)            // 槽位立即可复用
  → 主循环: DrainResults()         // 消费者按自己节奏批量取
```

不再有 `done_queue`。结果走 `ResultStore`——工人 Push，消费者 Drain。

## 普通命令（1 个分片）

```
-m:Calc -f:add -v:a|1,b|2
→ Task 有一个分片: {mod_id="Calc", func_id="add"}
→ Step() 发射 "Calc.add" → 模块回调 → 完成
```

## 多分片工作流

```cpp
REGISTER_FUNC("render", "逐帧渲染", {
    RenderFrame(frame_);
    frame_++;
    if (frame_ < total_) {
        auto next = std::make_unique<ParmarPack>();
        next->mod_id  = GetName();
        next->func_id = "render";
        pack->owner_task->PushShard(std::move(next));  // 追加下一帧
    }
    pack->success = true;
});
```

## 暂停 / 恢复

```
task->Pause();        // 当前分片跑完后暂停
task->Resume();       // 从断点继续
task->GetProgress();  // 0.0 ~ 1.0
```

暂停只在**分片之间**生效，当前正在跑的分片不受影响。

## 取消

```
task->Cancel();       // 状态 → FAILED，阻止后续分片
```

同样，当前分片跑完才生效。

## 死任务？分片内部无法打断

C++ 没法安全杀线程。如果一个分片进了死循环，`Cancel` 救不了。解决方案：把分片拆小（< 100ms）。
