# 线程安全 — 框架保证

## 你的回调在 worker 线程上跑

```cpp
REGISTER_FUNC("work", "...", {
    // 这里运行在 ThreadPool 的 worker 线程上
    // 不是主线程
});
```

## 安全的

- 读写 `pack` — 每个 task 有自己的 pack
- 调 `LOG_PLAIN(...)` — 全局输出锁保护
- 用 `std::atomic` — 标准 C++ 原子变量安全
- 调 `pack->owner_task->PushShard(...)` — shards_mutex_ 保护

## 不安全的

- 在回调之间共享非原子数据
- 跨回调持有其他模块数据的指针
- 回调里死循环（会阻塞 worker 线程）

## 插件卸载安全

`UnloadModule` 在卸载共享库之前会等所有正在执行的 Slot 完成。`Slot::Run()` 还额外持有 shared_ptr 双重保险。库的卸载由 `platform::SharedLibrary` 的 RAII 析构自动处理（Windows 上 `FreeLibrary`，Linux/macOS 上 `dlclose`）。**你不需要操心这个。**

## 用 LOG_PLAIN，不要用 std::cout

```cpp
// ❌ 不要
std::cout << "hello" << std::endl;

// ✅ 用这个
LOG_PLAIN("hello");
```
