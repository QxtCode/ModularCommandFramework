# 线程安全 — 框架保证

## 你的回调在 worker 线程上跑

```cpp
REGISTER_FUNC("work", "...", {
    // 这里运行在 ThreadPool 的 worker 线程上
    // 不是主线程
});
```

## 安全的

- 读写 `pack` — 每个 task 有自己的 pack
- 调 `LOG_PLAIN(...)` — 全局输出锁保护
- 用 `std::atomic` — 标准 C++ 原子变量安全
- 调 `pack->owner_task->PushShard(...)` — shards_mutex_ 保护

## 不安全的

- 在回调之间共享非原子数据
- 跨回调持有其他模块数据的指针
- 回调里死循环（会阻塞 worker 线程）

## 插件卸载安全

`UnloadModule` 的顺序是：`OnShutdown()` → `RemoveSignal("模块.*")` → 释放模块对象 →
`FreeLibrary`/`dlclose`（`platform::SharedLibrary` 的 RAII 析构）。

v2.6 起 `Emit` 是快照式（锁内拷贝信号 `shared_ptr`，锁外执行 Slot），因此
`RemoveSignal`/`UnloadModule` **不会等待正在执行的慢回调**：

- `Slot::Run()` 持有的 `shared_ptr` 保证**模块对象**不在回调中途被析构；
- 但 DLL 句柄在 `UnloadModule` 返回前就会释放，框架**不保证**在途回调的代码页仍有效。

结论：热卸载只在模块空闲时做；有命令在跑时先等它结束（或让模块在 `OnShutdown()` 里
自行等在途回调归零）。**不要**依赖「卸载会等回调」的旧行为（那是 v2.4 的语义）。

## 用 LOG_PLAIN，不要用 std::cout

```cpp
// ❌ 不要
std::cout << "hello" << std::endl;

// ✅ 用这个
LOG_PLAIN("hello");
```
