# 开发手册：从「能写」到「写好」

> 面向自学一年 C++ 的开发者：不讲语法，只讲「这个项目里，你现在能碰什么、怎么碰、先别碰什么」。
> 前提：先读 [14-SDK原理](14-SDK原理.md)（模块 WHAT vs 内核 HOW 分离），熟悉类/继承/虚函数/`shared_ptr`/lambda/简单模板。

---

## 0. 一句话结论

| 你现在要做的 | 结论 |
|-------------|------|
| 写一个自己的模块（命令） | ✅ 现在就能做，安全区 |
| 写任务「存储」后端 | ✅ 接口已接好，你只写实现（安全区） |
| 写任务「延迟调度」 | 🟡 接口+实现已就绪，但**没接进引擎**，等你来接线（进阶练手） |
| 改 `main` 函数 | ⚠️ 大多数情况你**不该改 main**，改 `ShellApp` |

## 1. 能力分级清单：你现在能碰什么

**先做 ✅，再啃 🟡，🔴 先别碰。**

### ✅ 现在就能做（纯安全区，不碰并发时序）

| 活 | 文件/位置 | 为什么适合你 |
|----|-----------|-------------|
| 写无状态模块 | `modules/PrintModule.h` 照抄 | 就是 `REGISTER_FUNC` + 读参数 + 返回 |
| 写带计数的模块 | 用 `std::atomic<int>` 计数 | 一个原子变量，不需要懂锁 |
| 写隔离测试 | `test/core/*.cpp` | 5 行测一个类，是「用法说明书」 |
| 实现存储后端 | `FilePersistence`（见 §4） | 只实现接口，引擎一行不动 |
| 改配置 | `test_shell.cfg` / `--key=value` | 就是改数字 |
| 注册模块 | `core/ShellApp.h` 的 `SetupModules()` | 加一行 `AddModule` |

### 🟡 练手后能做（先啃懂并发三件套）

| 活 | 前置知识 | 难度 |
|----|---------|------|
| 多分片工作流 | 看懂 `Task::Step` + `PushShard` | ★★ |
| 把延迟调度接进引擎 | 看懂主循环 100ms 心跳（§5） | ★★★ |
| 写线程安全模块 | `mutex` + `condition_variable` + `atomic` | ★★★ |
| DLL 插件模块 | `EXPORT_MODULE` + `platform::SharedLibrary` | ★★★ |

### 🔴 暂时别碰（雷区，动了要懂完整时序）

| 位置 | 为什么危险 |
|------|-----------|
| `ShellEngine::MainLoop` / `WaitForWork` / `Shutdown` | 四步流水线 + detach 时序 |
| `ThreadPool::WorkerLoop` | `stop_` + `cv.wait` 退出条件 |
| `EventBus::Emit` | 快照式 Emit 的锁释放点 |
| `TasksPool::Acquire/Release` | 对象池并发安全 |

> 雷区不是「永远不能碰」，而是「碰之前先写测试证明现在的行为 + 改完跑全量回归」。§5 会在雷区边缘走一次。

## 2. 写一个模块（你的第一个任务）

### 2.1 最小模板（复制即可跑）

```cpp
// modules/GreetModule.h
#pragma once
#include "sdk/sdk.h"            // 一个 include 到位，不链 eventbus

class GreetModule : public ModuleBase {   // 继承 ModuleBase（不是 ModuleBaseObject！）
public:
    const char* GetName() const override { return "Greet"; }   // 必实现
    int GetVersion() const override { return 1; }              // 可选，默认 1

    bool OnInit() override {
        REGISTER_FUNC("hello", "打个招呼", {
            std::string name = pack->GetOr("name", "world");
            ModuleBase::SetResult(pack, "Hello, " + name + "!");
        });
        return true;   // false 会拒绝注册
    }
};
```

### 2.2 你要实现的 3 个接口

| 接口 | 必填 | 作用 |
|------|------|------|
| `const char* GetName()` | ✅ 必须 | 模块名，决定命令 `-m:Greet` 的 `Greet` |
| `bool OnInit()` | ✅ 必须 | 在这里 `REGISTER_FUNC` 注册所有命令 |
| `void OnShutdown()` | 可选 | 热卸载/退出时清理（默认空） |
| `int GetVersion()` | 可选 | 默认返回 1 |

> `REGISTER_FUNC(id, 描述, { 函数体 })` —— 函数体里自动有 `ParmarPack* pack`。
> `Execute / Help / ReturnValue` 是 IModule 的默认实现，接线是宿主的活（`ForEachFunc`），**都不用你写**。

### 2.3 参数接口 ParmarPack 速查（写模块最常用）

命令格式：`-m:Greet -f:hello -v:name|Alice,age|20`

| 调用 | 返回 | 用途 |
|------|------|------|
| `pack->Get("name")` | `optional<string>` | 取第一个值，可能空 |
| `pack->GetOr("name", "world")` | `string` | 空则给默认值 |
| `pack->GetAs<int>("age")` | `optional<int>` | 按类型取，解析失败空 |
| `pack->GetAsOr<int>("age", 0)` | `int` | 类型取 + 默认值 |
| `pack->GetAsOr<bool>("f")` | `bool` | `"true"/"1"/"yes"` 为真 |
| `pack->Has("name")` | `bool` | 有这键没 |
| `pack->GetAll("tag")` | `const vector<string>&` | 取该键全部值（多值） |

**写结果**（推荐用收尾助手）：

```cpp
ModuleBase::SetResult(pack, "结果字符串");                     // 成功：success=true + return_value
ModuleBase::SetError(pack, ErrorCode::INVALID_PARAMS, "参数不对"); // 失败
// 更底层（一般用不到）：pack->success / pack->return_value / pack->error.{code,message}
```

### 2.4 注册进框架（改 `ShellApp`，不是 `main`）

`core/ShellApp.h` 的 `SetupModules()` 里加一行 `mgr.AddModule(std::make_unique<GreetModule>());`，
运行后敲 `-m:Greet -f:hello -v:name|张三` 即可。

## 4. 存储 `ITaskPersistence` —— 已接好，你来扩展后端

现状：存储闭环（暂停→保存→恢复）**已经通了**，`ShellApp` 里已 `engine_->SetTaskPersistence(store_.get())`。你的活是「写一个新后端」，不是接线。

### 4.1 接口定义（`core/ITaskPersistence.h`，5+1 个方法）

| 方法 | 签名 | 人话 |
|------|------|------|
| `Save` | `void Save(const TaskRecord&)` | 存/覆盖一个任务快照，**幂等** |
| `Load` | `optional<TaskRecord> Load(uint32_t id) const` | 读快照，没有就返回空 |
| `Delete` | `void Delete(uint32_t id)` | 删快照（任务完成后调） |
| `LoadAll` | `vector<TaskRecord> LoadAll() const` | 读所有**没结束**的任务（启动恢复用） |
| `GC` | `void GC()` | 清掉已结束（COMPLETED/FAILED）的记录 |
| `IsAvailable` | `bool IsAvailable() const` | 后端不可用就退化纯内存（默认 true） |

### 4.2 快照结构 `TaskRecord`

```cpp
struct TaskRecord {
    uint32_t    task_id = 0;
    std::string state;            // "IDLE" | "RUNNING" | "PAUSED" | "FAILED" | "COMPLETED"
    size_t      current_shard = 0;   // 跑到第几个分片
    size_t      declared_total = 0;  // 总分片数
    std::string shards_json;         // ★ 分片序列化数据（含 mod/func/params，已转义）
    int64_t     created_at_ms = 0;
    int64_t     scheduled_at_ms = 0; // 0 = 非延迟任务
    int         retry_count = 0;
    int         max_retries = 0;
};
```

> `shards_json` 里**不含裸换行**（`ParmarPack::ToJson` 把 `\n` 转成 `\\n`），所以可以「每行一个字段」安全存文件。

### 4.3 实战：教学版文件后端

> 框架里**已有真实现** `core/TaskFilePersistence.h`（每任务一个 `task_<id>.dat`）。
> 下面是教学版，展示模式；`Delete`（一行 `std::filesystem::remove`）、`LoadAll`/`GC`（遍历目录）、
> `ParseId`（从文件名取 id）从略，照 `TaskFilePersistence.h` 抄即可。

```cpp
#pragma once
#include <fstream>
#include <mutex>
#include <filesystem>
#include "core/ITaskPersistence.h"

// 极简文件持久化：每个任务一个文件 <dir>/task_<id>.dat，每行 "key=value"
class FilePersistence : public ITaskPersistence {
public:
    explicit FilePersistence(std::string dir) : dir_(std::move(dir)) {}

    void Save(const TaskRecord& r) override {
        std::lock_guard<std::mutex> lk(mutex_);
        std::ofstream f(path(r.task_id), std::ios::trunc);
        if (!f) return;                       // 静默失败：不抛异常
        f << "state="       << r.state          << "\n"
          << "shard="       << r.current_shard  << "\n"
          << "total="       << r.declared_total << "\n"
          << "created="     << r.created_at_ms  << "\n"
          << "scheduled="   << r.scheduled_at_ms<< "\n"
          << "retry="       << r.retry_count    << "\n"
          << "max_retries=" << r.max_retries    << "\n"
          << "shards_json=" << r.shards_json    << "\n";
    }

    std::optional<TaskRecord> Load(uint32_t task_id) const override {
        std::lock_guard<std::mutex> lk(mutex_);
        std::ifstream f(path(task_id));
        if (!f) return std::nullopt;
        try {
            TaskRecord r;  r.task_id = task_id;
            std::string line;
            while (std::getline(f, line)) {
                size_t eq = line.find('=');
                if (eq == std::string::npos) continue;
                std::string k = line.substr(0, eq), v = line.substr(eq + 1);
                if      (k == "state")       r.state          = v;
                else if (k == "shard")       r.current_shard  = std::stoull(v);
                else if (k == "total")       r.declared_total = std::stoull(v);
                else if (k == "created")     r.created_at_ms  = std::stoll(v);
                else if (k == "scheduled")   r.scheduled_at_ms= std::stoll(v);
                else if (k == "retry")       r.retry_count    = std::stoi(v);
                else if (k == "max_retries") r.max_retries    = std::stoi(v);
                else if (k == "shards_json") r.shards_json    = v;
            }
            return r;
        } catch (...) { return std::nullopt; } // 文件损坏则当作不存在
    }
    // Delete / LoadAll / GC / ParseId：从略，见 core/TaskFilePersistence.h
private:
    std::string path(uint32_t id) const { return dir_ + "/task_" + std::to_string(id) + ".dat"; }
    std::string dir_;
    mutable std::mutex mutex_;
};
```

> **新手必踩的坑**：`LoadAll`/`GC` 已持锁再调公开的 `Load`（内部也 `lock_guard`）=
> 对同一个 `std::mutex` 重复加锁 → **死锁**。正确做法：抽一个不加锁的私有 `LoadUnlocked`，
> 公开方法加锁后调它。这就是 `MemPersistence` 每个公开方法各自加锁、互不嵌套调用的原因。

### 4.4 接进框架（改 `ShellApp` 一行）

```cpp
// 成员：把类型换成你的后端（ShellApp 默认是 TaskFilePersistence）
std::shared_ptr<FilePersistence> store_;
// 构造：
store_ = std::make_shared<FilePersistence>(platform::Process::ExeDir() + "task_store");
```

> `store_` 是 `shared_ptr` 且传 `.get()` 给引擎，只要「声明在 engine 之前」不变，换类型不影响析构顺序。
> **捷径**：直接用 `TaskFilePersistence`，换类型 + 传目录路径即可。

### 4.5 三条硬性约束（任何后端都要遵守）

1. **线程安全**：Worker 和主线程可能同时调 `Save/Load`，内部必须加锁。
2. **异常安全**：`Save/Load/Delete` 失败要静默（返回 nullopt / 什么都不做），**不抛异常**——Worker 收尾抛异常会崩掉整个 shell。
3. **生命周期**：后端必须比 `ShellEngine` 活得久（`store_` 声明在 `engine_` 之前）。

参考：`NullPersistence`（零开销空实现）、`MemPersistence`（内存实现）、`TaskFilePersistence`（已实现的文件后端）。

## 5. 延迟 `ITaskScheduler` —— 接口已就绪，等你接线（本手册最重要）

存储已接，延迟**未接**：接口（`core/ITaskScheduler.h`）+ 内存实现 `MemScheduler` + 测试都有，只差接进引擎。

### 5.1 接口定义（5 个方法）

| 方法 | 签名 | 人话 |
|------|------|------|
| `Schedule` | `void Schedule(uint32_t task_id, time_point at)` | 登记「任务 id 在 at 时刻到期」 |
| `Cancel` | `void Cancel(uint32_t task_id)` | 取消一个延迟 |
| `PollDue` | `vector<uint32_t> PollDue(time_point now)` | 取出「所有已到期」的 task_id |
| `NextWakeup` | `optional<milliseconds> NextWakeup(now) const` | 距最近到期还有多久（供 cv 超时） |
| `PendingCount` | `size_t PendingCount() const` | 还有几个没到期 |

先读实现和测试（别读接口猜）：`core/MemTaskStore.h` 的 `MemScheduler`（`map<time_point, vector<id>>` + mutex）、`test/core/task_store_test.cpp` 的 `MockSchedulerTest`（每个 5 行，就是用法）。

### 5.2 实战：把延迟接进引擎（6 步，难度递增）

**核心思路**：延迟 = 「暂停的任务 + 调度器定时放行」。任务先 `Acquire` 再 `Pause`，调度器记到期时间，主循环每轮 `PollDue` 到期就 `Resume` + 重新入队。
> ⚠️ 第 4 步动 `MainLoop`（雷区边缘），但只「加一行调用 + 一个私有方法」，不改现有四步逻辑。每步做完跑测试。

#### 第 1 步：`ShellEngine` 加调度器入口（✅ 仿 `SetTaskPersistence`）

```cpp
// 公开接口（放在 SetTaskPersistence 旁边）
void SetTaskScheduler(ITaskScheduler* s) { scheduler_ = s; }
// 成员（放在 store_ 旁边）
ITaskScheduler* scheduler_{nullptr};
```

#### 第 2 步：抽 `RunTask` 私有方法（✅ 消除重复）

把 `SubmitTask` 里 Worker lambda 的「跑任务 + 暂停保存 + 推结果 + 释放」样板抽出来，`SubmitTask` 和后面 `ProcessDueTasks` 共用：

```cpp
void RunTask(Task* task);   // 私有声明

inline void ShellEngine::RunTask(Task* task) {
    workers_->Enqueue([this, task]() {
        try { while (task->Step(EventBus::GetInstance())) {} }
        catch (...) {
            auto* cp = task->CurrentPack();
            if (cp) { cp->success = false; cp->error.code = ErrorCode::INTERNAL_ERROR;
                      cp->error.message = "Unhandled exception in task"; }
        }
        if (task->GetState() == Task::State::PAUSED && store_)
            store_->Save(task->ExportRecord());
        auto* cp = task->CurrentPack();
        if (cp) ResultStore::Get().PushResult(task->GetID(), std::make_unique<ParmarPack>(*cp));
        tasks_->Release(task);
        shared_->cv.notify_one();
    });
}
```

`SubmitTask` 尾部改成一行 `RunTask(task);`，行为完全不变——先跑测试确认，再往下。

#### 第 3 步：`TaskManagerModule` 加 `-f:delay` 命令（✅）

```cpp
// 构造：加一个 ITaskScheduler* 参数
TaskManagerModule(TasksPool& pool, ThreadPool& workers,
                  ITaskPersistence* store = nullptr,
                  ITaskScheduler* scheduler = nullptr)
    : pool_(pool), workers_(workers), store_(store), scheduler_(scheduler) {}

// OnInit 里加：
REGISTER_FUNC("delay", "延迟执行 (-v:sec|秒 -v:mod|模块 -v:func|函数)", {
    int sec = pack->GetAsOr<int>("sec", -1);
    std::string mod = pack->GetOr("mod", "");
    std::string fn  = pack->GetOr("func", "");
    if (sec < 0 || mod.empty() || fn.empty() || !scheduler_) {
        ModuleBase::SetError(pack, ErrorCode::INVALID_PARAMS,
            "Usage: -m:TaskManager -f:delay -v:sec|N -v:mod|M -v:func|F");
        return;
    }
    auto p = std::make_unique<ParmarPack>();
    p->mod_id = mod;  p->func_id = fn;
    Task* t = pool_.Acquire(std::move(p));
    if (!t) { ModuleBase::SetError(pack, ErrorCode::INTERNAL_ERROR, "No free task slot"); return; }

    t->Pause();   // 先暂停住，等调度器放行
    scheduler_->Schedule(t->GetID(),
        std::chrono::system_clock::now() + std::chrono::seconds(sec));
    ModuleBase::SetResult(pack, "Task " + std::to_string(t->GetID())
                          + " scheduled in " + std::to_string(sec) + "s");
});
// 成员加：ITaskScheduler* scheduler_;
```

#### 第 4 步：主循环放行到期任务（⚠️ 动 `MainLoop`，加一行）

```cpp
inline void ShellEngine::MainLoop() {
    while (shared_->running.load()) {
        DrainResults();
        FlushMetrics();
        ProcessDueTasks();   // ★ 新增这一行
        WaitForWork();
        ProcessInput();
    }
}

inline void ShellEngine::ProcessDueTasks() {
    if (!scheduler_) return;
    auto due = scheduler_->PollDue(std::chrono::system_clock::now());
    for (uint32_t id : due) {
        Task* task = tasks_->FindTask(id);
        if (!task) continue;          // 任务已释放/不存在，跳过
        task->Resume();               // PAUSED → RUNNING
        RunTask(task);                // 重新入队（第 2 步抽的方法）
    }
}
```

这就是「极小化改动」：不碰四步内部，只在之间**插入**一步。`FindTask` 已在 `TasksPool` 里。

#### 第 6 步：隔离测试（✅）

```cpp
// test/core/scheduler_wiring_test.cpp
TEST(SchedulerWiring, 延迟后自动放行) {
    TasksPool pool(4);
    ThreadPool workers(2);
    MemScheduler sched;

    auto p = std::make_unique<ParmarPack>();   // 模拟一个要延迟的任务
    p->mod_id = "Greet"; p->func_id = "hello";
    Task* t = pool.Acquire(std::move(p));
    t->Pause();
    sched.Schedule(t->GetID(), std::chrono::system_clock::now()
                               + std::chrono::milliseconds(200));

    auto due = sched.PollDue(std::chrono::system_clock::now() + std::chrono::milliseconds(300));
    ASSERT_EQ(due.size(), 1u);
    EXPECT_EQ(due[0], t->GetID());
}
```

### 5.3 为什么延迟比存储难（诚实说）

| 维度 | 存储 `ITaskPersistence` | 延迟 `ITaskScheduler` |
|------|------------------------|----------------------|
| 接口接没接 | ✅ 已接 | ❌ 未接，要你接 |
| 要动引擎吗 | 不用（只写后端） | 要（加一步 `ProcessDueTasks`） |
| 要懂主循环吗 | 不用 | 要（理解 100ms 心跳 + `PollDue`） |
| 雷区风险 | 无 | 边缘（`MainLoop` 加一行） |

**建议路线**：先做 §4 的 `FilePersistence`（纯安全区，建立信心），再做 §5 延迟接线（按步骤，每步跑测试）。
> `WaitForWork` 的 `NextWakeup()` 优化（固定 100ms 超时 → 距最近到期时间）是锦上添花，不改也能用（最多晚 100ms 放行）。等 1~6 步跑通、懂了 `cv.wait_for` 的 predicate 再单独碰——那才是真正的雷区。

## 6. 后续开发原则（照做就稳）

### 6.1 加功能六步法

1. 三句话说清需求（命令是什么 / 做什么 / 成功失败返回啥）。
2. 画依赖边界：哪些我知道、哪些要查。
3. 写最傻的隔离测试（不依赖 `ShellEngine`，手工组装最小环境）。
4. 一次只加一个变量（一个测试只验一件事）。
5. 破坏测试：暂停不存在的任务、双暂停、并发暂停。
6. 集成只改一行注册（`ShellApp::SetupModules`）。

### 6.2 安全区 / 雷区（v2.8 版）

**安全区**：`modules/*.h`、`sdk/` 派生类、`ITaskPersistence` 的实现、`test/`、`ShellApp::SetupModules`、`Task` 的新方法。
**雷区**：`ShellEngine::MainLoop/WaitForWork/Shutdown/StartInputThread`、`ThreadPool::WorkerLoop`、`EventBus::Emit`、`TasksPool::Acquire/Release`。

### 6.3 铁律

1. **析构顺序**：成员声明顺序 = 析构的逆序。`store_`/`scheduler_` 必须声明在 `engine_` 之前（比引擎活得久）。
2. **一次一个变量**：一次 PR 只做一件事（接口 + 测试），别夹带重构。
3. **先测试后集成**：新模块独立测试全绿 → 全量回归绿 → 集成。
4. **Release 后别用旧指针**：`pool.Release(t)` 之后 `t` 已被 `Reset`，再用就是悬空。
5. **看不懂就看测试**：`test/` 是每个类的「用法说明书」，5 行一个用例，比读源码快。

## 7. 可抄的练手路线（按顺序）

1. **热身**：照 §2 写一个 `GreetModule`，注册进 `ShellApp`，跑通。
2. **存储**：照 §4 写一个文件持久化后端（或直接读已有的 `core/TaskFilePersistence.h` 对照学习），写隔离测试，换进 `ShellApp`，`pause` 后重启进程再 `resume` 验证真的落盘了。
3. **延迟**：照 §5 接 `ITaskScheduler`，跑通 `-f:delay -v:sec|3 -v:mod|Print -v:func|1`。
4. **进阶（可选）**：把 `WaitForWork` 换成 `NextWakeup()`，消除 100ms 固定延迟。

做完这四步，你就完整走了一遍「写模块 → 写后端 → 接调度器 → 碰主循环」，从安全区一路进阶到雷区边缘，对框架的理解会比只读文档深一个量级。
