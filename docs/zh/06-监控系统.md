# 监控系统 — 看框架状态

## MetricsCollector 三条命令

| 命令 | 用途 | 占 Task 槽？ |
|------|------|:---:|
| `-f:show` | 控制台打印即时快照 | 是 |
| `-f:metrics` | 一行精简摘要 | 是 |
| `-f:dashboard` | 启动 `shell_monitor.exe` 独立 FTXUI 全屏窗口 | **否** |

### 1. 内联快照

```
> -m:MetricsCollector -f:show
[OK] === test_shell v2.5 Dashboard ===
  CPU:     0.00%
  Tasks:   0 active / 8 total
  Modules: 4 loaded
  Uptime:  15s
```

帮助: `-m:MetricsCollector -f:help`

### 2. 一行摘要

```
> -m:MetricsCollector -f:metrics
[OK] Uptime:15s Tasks:0/8 Modules:4 Signals:12 Threads:4 Stuck:0
```

### 3. 外部仪表盘（零 Task 成本）

```
> -m:MetricsCollector -f:dashboard
[OK] Dashboard launched in new window (close with q)
```

用 `CreateProcess` + `CREATE_NEW_CONSOLE` 启动 `shell_monitor.exe` 作为独立进程。实时读取共享内存，FTXUI 渲染——不占框架 Task 槽位，不阻塞控制台输入。

也可以手动启动：
```
终端 1: ./test_shell.exe
终端 2: ./shell_monitor.exe        ← q 退出, p 暂停
```

## 原理

```
test_shell.exe              shell_monitor.exe
┌──────────────────┐        ┌──────────────────┐
│ MetricsCollector │ 共享    │ main()           │
│   Flush()        │─内存─→│ 读取 MetricsData  │
│   主循环每轮都写   │        │ FTXUI 渲染面板    │
└──────────────────┘        └──────────────────┘
```

- MetricsCollector 是普通 IModule，和其他模块一样加载
- 写共享内存 (CreateFileMapping)
- 监控进程读同一块内存 (OpenFileMapping)
- 框架崩了 → 面板显示 NO SIGNAL
- 面板崩了 → 框架照常
