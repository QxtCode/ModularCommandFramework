# AI 辅助开发指南

test_shell 包含自动记忆系统（`CLAUDE.md` + `memory/`），帮助 AI 编程助手理解代码库。本指南说明如何有效使用它。

## 自动记忆（Claude Code）

项目在 `.claude/projects/.../memory/` 维护持久记忆存储。每个文件记录一条关于代码库的事实——架构、关键类、构建步骤、测试策略。

当你让 AI 助手在此项目上工作时，它会自动读取这些记忆作为上下文。无需每次都解释架构。

### 记忆文件

| 文件 | 内容 |
|------|------|
| `project-overview.md` | 项目总览、v2.5 变化、源码布局 |
| `architecture.md` | 数据流、ShellEngine 四步流水线、ResultStore、Slot 防线 |
| `key-classes.md` | API 速查：ShellEngine、ResultStore、EventBus、Config |
| `build-guide.md` | 配置、构建、运行、测试方法 |
| `test-strategy.md` | 测试模式：原子计数器、激进清理、不稳定检测 |

### 如何更新记忆

做出重大变更（新功能、重构、API 改动）后，让 AI 更新相关记忆文件：

> "更新记忆，反映新增的平台抽象层"

AI 会读取当前代码，对比已有记忆，按需更新或创建文件。

## 项目约定（给 AI 助手）

### 代码风格
- C++20，header-only 内核（实现在 `.h` 文件中内联）
- 中文注释配英文代码
- 全面 RAII——无手动资源管理
- 测试验证用原子计数器（引擎测试中禁止 polling ResultStore）
- 输出用 `LOG_PLAIN`（禁止裸 `std::cout`）

### 架构规则
- 模块实现 `IModule` 接口：`GetName()`、`OnInit()`、`OnShutdown()`
- 在 `OnInit()` 中用 `REGISTER_FUNC(名称, 描述, lambda)` 注册函数
- 工作线程循环执行 `task->Step(bus)`
- 结果通过 `ResultStore` 流转（生产者-消费者模式）
- `ShellEngine` 拥有主循环；`main()` 只负责组装

### 平台规则
- **严禁**在 `core/platform/` 之外添加 `#ifdef _WIN32` 或 `#ifdef __linux__`
- 使用 `platform.h` 中的 `PLATFORM_WINDOWS`、`PLATFORM_LINUX`、`PLATFORM_MACOS`
- 使用 `PLATFORM_EXPORT` 代替 `__declspec(dllexport)`
- 使用 `platform::SharedLibrary`、`platform::SharedMemory`、`platform::Process` 处理 OS API
- 新平台功能在 `_win.cpp` 和 `_posix.cpp` 成对文件中实现

### 测试规则
- 引擎测试：用原子计数器（不用 ResultStore）
- Fixture SetUp：`AggressiveCleanup()`——清空 ResultStore，排空 CommandParser
- 用 `--gtest_repeat=3` 检测不稳定测试
- 平台测试：跨平台编写（测边界值，不测 OS 特定行为）
- 慢速测试（60s+）从 CI 排除：`--gtest_filter=-StressGraduated.*:Stress60s.*`

### 构建规则
- 构建：`cmake --preset debug && cmake --build --preset debug`
- 测试：`cd out/build/debug && ./test_runner --gtest_filter=-StressGraduated.*:Stress60s.*:PeakStressTest.*`
- 新增 `.cpp`：加入对应 `CMakeLists.txt`
- 平台相关 `.cpp`：加入 `if(WIN32)` / `else()` 分支
